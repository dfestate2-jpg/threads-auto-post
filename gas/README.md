# 入金自動記入（Google Apps Script）

freee の口座明細から **入金だけ** を取り出し、入金管理スプレッドシートの
月次シートへ「入金日 / 入金者 / 入金額」を追記する。

既に稼働している **「振込自動記入（出金版）」の姉妹スクリプト**。
作りは意図的にそろえてある（関数名・`設定` の書き方・`_sync` による重複防止・
リフレッシュトークンの即保存・`ALERT_MAIL` へのエラー通知）。

| ファイル | 内容 |
|---|---|
| `入金自動記入.gs` | Apps Script に貼り付けるコード一式 |

---

## 出金版との違い

| 項目 | 振込（出金版） | 入金版 |
|---|---|---|
| `entry_side` | `expense` | **`income`** |
| 見出し行 / データ開始行 | 1行目 / 2行目 | **2行目 / 3行目** |
| 月次シート名 | `yyyyMM` | **`yyyy/MM`**（例 `2026/08`。既存シートに合わせる） |
| 書き込む列 | A・B・C（決め打ち） | **見出し行の文字から自動判定**（現状 B・D・E。契約者名・契約締結日・備考には触らない） |
| 月次シートが無いとき | `insertSheet` + 見出し生成 | **「コピー」シートを複製**（テンプレが無ければ作らずにエラー） |
| 入金日の書き方 | 毎行 | **同じ日付が続く行は空欄**（既存の手入力に合わせる） |
| 最終行の判定 | B列 | **C列（入金者）** |
| 名義の整形 | 全角英数→半角 | **半角カナ→全角**＋法人格略号の除去を追加 |
| 取り込み開始日 | なし | **あり（必須）** |
| 見張り | なし | **明細が届かなくなったらメール** |

### 名義の整形

銀行から届く摘要は半角カナなので、既存シートの表記（全角カタカナ）に合わせて変換する。

| 摘要（freee） | 入金者欄 |
|---|---|
| `ﾌﾘｺﾐ ｶ)ﾀﾏﾎｰﾑ` | `タマホーム` |
| `振込 ｸﾗﾊｼ ｼﾞﾕﾝﾔ` | `クラハシ ジユンヤ` |
| `ﾌﾘｺﾐ ﾀﾞｲｷｮｳｱﾅﾌﾞｷ` | `ダイキョウアナブキ` |
| `ﾔﾏﾀﾞｼｮｳｼﾞ(ｶ` | `ヤマダショウジ` |

削り切って空になる摘要（`ﾌﾘｺﾐ` だけ等）は、**空欄にせず元の摘要を残す**。

## セットアップ

### 0. 別プロジェクトにすること

**振込（出金）用スクリプトとは別の Apps Script プロジェクトを作る。**

- `トリガー登録` はそのプロジェクトのトリガーを全部消してから作り直すため、
  同居させると振込側のトリガーが消える
- `FREEE_REFRESH_TOKEN` は使い捨て。同じ値を2つのスクリプトで共有すると、
  片方が更新した瞬間にもう片方が動かなくなる
  → **`step1` / `step2` はこのプロジェクトで改めて実行し、専用のトークンを取る**

### 1. コードを貼る

新しい Apps Script プロジェクトを作り、`入金自動記入.gs` の中身を貼り付ける。
プロジェクト名は「入金自動記入」などにしておくと後で探しやすい。

### 2. スクリプトプロパティを設定する

［プロジェクトの設定］＞［スクリプト プロパティ］

| キー | 値 |
|---|---|
| `FREEE_CLIENT_ID` | freee アプリの client_id（振込版と同じ値でよい） |
| `FREEE_CLIENT_SECRET` | freee アプリの client_secret（同上） |
| `FREEE_COMPANY_ID` | 事業所ID（`step3_口座一覧表示` で分かる） |
| `FREEE_WALLETABLE_ID` | 入金が入る銀行口座のID（`どの口座か調べる` で分かる） |
| `SS_ID` | **入金管理ブック**のスプレッドシートID（URLの `/d/` と `/edit` の間） |
| `ALERT_MAIL` | エラー通知の宛先メールアドレス |

### 3. freee を認可する

1. `step1_認可URL表示` を実行 → ログのURLをブラウザで開いて許可
2. 表示された認可コードを `step2_認可コード登録` の `const code = ''` に貼る
3. `step2_認可コード登録` を実行（ログに「認可完了」と出れば成功）

### 4. 取り込み開始日を決める

`入金自動記入.gs` 冒頭の `設定.取り込み開始日` を、
**手入力済みの最後の入金日の翌日**にする。

```js
取り込み開始日: '2026-08-23',
```

**ここが一番大事。** 古い日付にすると、手で入れた行と同じ入金がもう一度書かれる。

### 5. 書き込む前に確認する

```
どの口座か調べる    … 入金明細が入っている口座IDを確認
摘要を確認する      … 摘要 → 入金者名 の変換結果を確認
状況を確認する      … 何件が新規として書かれるかを確認（書き込みはしない）
```

`状況を確認する` の出力に、**すでにシートに手で入れた入金が含まれていないこと**を必ず確かめる。
含まれていたら `取り込み開始日` を直す。

### 6. 実行 → 自動化

1. `入金を取り込む` を手動で1回実行し、シートを目で確認する
2. 問題なければ `トリガー登録` を実行
   - `入金を取り込む` … 4時間ごと
   - `入金が途絶えていないか見張る` … 毎日10時台

## 重複させない仕組み

| 段 | 仕組み |
|---|---|
| ① | `_sync_入金` シートに処理済みの明細IDを記録し、同じIDは二度書かない |
| ② | 書き込めた分のIDを **`finally` で必ず保存する** |
| ③ | `LockService` で多重起動を防ぐ |
| ④ | `取り込み開始日` より前の明細は取り込まない |

### ② について（出金版との差）

出金版は、追記ループが**全部終わってから**IDを保存している。

```js
明細.forEach(m => { 月シートに追記_(m); 済み.add(m.id); 件数++; });
if (件数 > 0) 処理済みID保存_(済み);   // ← ここまで来ないと保存されない
```

途中の1件で例外が出ると保存されないまま終わるため、**次回の実行で
「書けていた行」がもう一度書かれる**（＝スプレッドシートに重複が残る）。

入金版は保存を `finally` に移してこれを塞いでいる。
振込版にも同じ1行の修正を入れておくことを勧める。

## 書き込む列の決め方

列番号は決め打ちにしていない。**毎回、見出し行（2行目）の文字を読んで列を探す。**

```js
  見出し: { 入金日: '入金日', 入金者: '入金者', 入金額: '入金額' },
```

このため、シートの左に列が1つ足されても書き込み先はずれない。
見出しが見つからないときは、**黙って隣の列に書かずにエラーで止まる**（`ALERT_MAIL` に通知が飛ぶ）。

見出しの文字そのものを変えた場合は、上の設定を新しい文字に合わせること。

## 月次シートの名前

```js
  シート名の形式: 'yyyy/MM',   // 例: 2026/08
```

**既存シートの付け方に必ず合わせること。** 形式が違うと、同じ月のシートが二重にできる。

## 記入したくない入金を除外する

コード冒頭の `設定` に書き足すだけ。**半角カナ・全角の違いは自動で吸収する**ので、どちらか片方を書けば足りる。

```js
  除外_先頭: [],                                   // 摘要の「先頭」に来たら除外
  除外_含む: ['利息', 'リソク', 'ポイント', 'POINT'],  // 摘要の「どこかにあれば」除外
```

会社名に同じ言葉が入っていて巻き込まれる場合（例: `ﾜﾝﾎﾟｲﾝﾄｼｮｳｼﾞ`）は、
`除外_含む` から `除外_先頭` へ移すと先頭一致だけになる。

書き足したら `摘要を確認する` を実行する。摘要ごとに `［除外］` / `　記載　` が出るので、
**意図しないものが除外されていないか**をその場で確認できる。

## 明細が届かなくなったときに気づく

freee 側で銀行口座の連携が切れると、**エラーは出ないのに明細だけが来なくなる**。
`入金が途絶えていないか見張る` を毎日動かしておくと、
最後に確認できた明細から `設定.無音アラート日数`（既定5日）を過ぎた時点で
`ALERT_MAIL` へメールが飛ぶ。

## やり直したいとき

`記入をやり直す` を実行すると `_sync_入金` を空にして取り込み直す。
**シートに既に書かれた行は消えない**ので、自動で入った行を先に手で消しておくこと。
