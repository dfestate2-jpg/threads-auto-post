# 00. はじめての導入（プログラム未経験の方向け）

プログラムを触ったことがない方が、ひとりで最初から最後まで進められるように書いた手順書です。
専門用語は出てくるたびに日常の言葉で言い換えます。**ほとんどの作業はブラウザだけで終わります。**

所要時間 90分ほど / 月額 0円（開始時） / 手順 10ステップ

---

## 何をするシステムか

お客様から公式LINEにメッセージが届いたのに、社内の誰も返信していない。
その状態を自動で見つけて、**返信するまで社内に何度でも知らせ続ける**システムです。

```
10:00  お客様「内見の予約をしたいのですが」
11:00  返信なし → 社内Slackに1回目の通知
12:00  まだ返信なし → 2回目の通知
13:00  まだ返信なし → 3回目。責任者にも届く
13:30  担当者が返信 → 通知はここで止まる
```

通知の間隔（1時間ごと／2時間ごと／3時間ごと／通知しない）、営業時間、
誰に知らせるかは、あとから管理画面で自由に変えられます。

> **このシステムの一番の役目**
> お客様のLINEを見落とさないこと。そのため「返信したかどうか怪しい」ときは、
> **通知を止めずに鳴らし続ける**作りにしてあります。
> うるさく感じる場合は間隔を延ばせますが、勝手に黙ることはありません。

---

## 先に覚える7つの言葉

意味が分からなくても手順どおり進めれば動きますが、読んでおくと「今なにをしているのか」が分かります。

| 言葉 | 日常の言葉で言うと |
|------|-------------------|
| **サーバー** | システムを24時間動かしておく場所。Netlify という会社の場所を無料で借ります |
| **データベース（台帳）** | お客様のメッセージ・担当者・対応状況を貯めておくノート。Supabase を無料で借ります |
| **Webhook** | LINEが「今メッセージが届きましたよ」と自動で知らせてくれる仕組み。これが無いとシステムは何も気づけません |
| **Cron（クロン）** | 「5分おきに見回りする」タイマー。未返信がないか確認して通知を送る係 |
| **環境変数** | パスワードや鍵を、プログラムの中に書かずに保管しておく場所。今回は7つ登録します |
| **リポジトリ** | プログラムの保管庫。GitHub にあります |
| **デプロイ** | 保管庫のプログラムを、実際に動く状態にすること。「公開する」と考えて構いません |

---

## 用意するアカウント

4つです。すべて無料で始められます。公式LINEはお持ちのものを使います。

| サービス | 役割 | 費用 |
|---------|------|------|
| GitHub | プログラムの保管庫。**すでにあります** | 0円 |
| Supabase | 台帳（データベース） | 0円 |
| Netlify | システムを動かす場所 | 0円 |
| Slack | 社内への通知先。今回**新しく作ります** | 0円 |

> **将来かかる可能性のある費用**
> 管理画面からお客様へ返信するとき、LINEの「メッセージ通数」を消費します。
> 無料プランは月200通までなので、**1日7件以上返信する**ならLINE公式アカウントの
> ライトプラン（月5,000円・5,000通）が必要になります。
> 社内への通知はSlackなので、こちらは何通送っても0円です。

# 手順

## 01. 保管庫の設定を直す（GitHub / 1分）

最初に空っぽの状態から作った都合で、初期設定がずれています。

1. リポジトリのページを開く
2. 上のタブから **Settings**
3. **General** の **Default branch** の欄を探す
4. 鉛筆マークをクリックし、`main` を選んで **Update**

> 「どれが正式版のプログラムか」を指定する設定です。
> ここが正しくないと、このあとの公開作業で間違ったものが公開されることがあります。

---

## 02. 台帳をつくる（Supabase / 10分）

1. https://supabase.com/ で **Start your project** → GitHubアカウントでログイン
2. **New project**
3. 名前は自由（例：`line-reminder`）
4. **Database Password** は自動生成されたものをそのまま使い、**必ずメモに控える**
5. Region は **Northeast Asia (Tokyo)**
6. **Create new project**。完了まで2分ほど待つ

### 接続先の文字列を取り出す

1. 左メニュー下の **Project Settings**（歯車マーク）
2. **Database** → **Connection string**
3. **URI** タブを選んでコピー
4. 文字列の中の `[YOUR-PASSWORD]` を、手順4で控えたパスワードに置き換える
5. 末尾に `?sslmode=require` を足す

```
# できあがりの形（これが1つ目の環境変数です）
postgresql://postgres:あなたのパスワード@db.xxxx.supabase.co:5432/postgres?sslmode=require
```

> 🛑 **取り扱い注意**
> この文字列を知っている人は、お客様の情報をすべて見られます。
> メールやチャットに貼らず、パスワード管理ツールかメモ帳に控えてください。

---

## 03. Slackをつくる（Slack / 10分）

1. https://slack.com/get-started で新しいワークスペースを作成
2. チャンネルを1つ作る（例：`#line-未返信リマインド`）
3. **担当者全員をワークスペースとチャンネルに招待する**

### 通知の受け口（URL）を発行する

1. https://api.slack.com/apps を開く
2. **Create New App** → **From scratch**
3. 名前は `未返信リマインド` など。ワークスペースは手順1で作ったものを選ぶ
4. 左メニューの **Incoming Webhooks** を **On**
5. **Add New Webhook to Workspace** → 手順2のチャンネルを選んで **許可する**
6. 表示された `https://hooks.slack.com/services/...` をコピーして控える（2つ目の環境変数）

> 🛑 **ここが今回いちばんの落とし穴**
>
> 社内の連絡がふだんLINEなら、Slackは**誰の習慣にもない新しいアプリ**です。
> システムが正しく通知しても、誰もアプリを開かなければ「見落とした」のと同じ結果になります。
>
> 導入時に、担当者全員に次をやってもらってください。
> - スマホにSlackアプリを入れる
> - そのチャンネルを開き、チャンネル名 → 通知 → **「すべてのメッセージ」** に変更する
> - チャンネルをミュートしない
>
> 既定では「メンションのみ」通知のため、**この設定をしないとシステムからの通知は鳴りません。**

---

## 04. 公式LINEの鍵を取る（LINE Developers / 10分）

1. https://developers.line.biz/ にLINEアカウントでログイン
2. プロバイダー → お使いの公式アカウントに対応する **Messaging API** チャネルを開く

> 🛑 **先にここを確認してください**
>
> **Messaging API設定** タブの **Webhook URL** の欄を見てください。
> - **空欄** → そのまま進めて大丈夫です
> - **何かURLが入っている** → **いったん止めてください。**
>   チャットボットや予約システムなど、別のツールがすでに使っています。
>   Webhook URLは1つしか設定できないので、上書きするとそのツールが動かなくなります。

### 値を2つ取り出す

| 取る場所 | 項目 |
|---------|------|
| **チャネル基本設定** タブ | チャネルシークレット（3つ目の環境変数） |
| **Messaging API設定** タブ | チャネルアクセストークン（長期）。「発行」ボタンを押すと出ます（4つ目） |

### 同じ画面でもう2つ設定を変える

- **Webhookの利用** → **オン**
- **応答メッセージ** → **オフ**

応答メッセージをオフにするのは、自動返信が返っていると「誰かが対応した」と
社内で誤解されるためです。システムの判定自体には影響しません。

## 05. システムを公開する（Netlify / 20分）

### 残り3つの値を自分で作る

**32文字以上のでたらめな英数字**を2つ用意してください。

| 名前 | 中身 |
|------|------|
| `CRON_SECRET` | でたらめな英数字32文字（5つ目） |
| `SESSION_SECRET` | 別のでたらめな英数字32文字（6つ目） |
| `APP_BASE_URL` | 公開後に決まるURL（7つ目・あとで設定） |

### Netlifyに繋ぐ

1. https://app.netlify.com/ に GitHubアカウントでログイン
2. **Add new site** → **Import an existing project**
3. **GitHub** を選び、`threads-auto-post` を選択
4. Branch は `main`、ビルド設定は**そのまま触らない**（設定ファイルが同梱されています）
5. デプロイ前に環境変数を入れる画面があれば、そこで6つ登録する。無ければ先にデプロイし、失敗してから次の手順で登録する

### 環境変数を登録する

**Site configuration** → **Environment variables** で、次の6つを登録します。

| 名前 | 入れる値 |
|------|---------|
| `DATABASE_URL` | 手順02の接続文字列（**Transaction pooler / 6543**） |
| `DIRECT_URL` | 手順02の接続文字列（**Session pooler / 5432**） |
| `LINE_CHANNEL_SECRET` | 顧客対応チャネルのチャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | 顧客対応チャネルのアクセストークン |
| `LINE_NOTIFY_CHANNEL_ACCESS_TOKEN` | 社内通知チャネルのアクセストークン |
| `LINE_NOTIFY_CHANNEL_SECRET` | 社内通知チャネルのチャネルシークレット |
| `LSTEP_RELAY_TOKEN` | 自分で作った文字列（Lステップの転送先URLに載せる） |
| `CRON_SECRET` | 自分で作った文字列 |
| `SESSION_SECRET` | 自分で作った文字列 |
| `APP_BASE_URL` | 公開されたサイトのURL（`https://〜.netlify.app`） |

> **`DATABASE_URL` と `DIRECT_URL` はポート番号が違うだけの別物です。**
> アプリが動くときは接続数を節約できる 6543、台帳の作り直し（マイグレーション）は
> 5432 を使います。逆にするとデプロイが失敗します。

> Slack を使う構成にする場合のみ `INTERNAL_SLACK_WEBHOOK_URL` を足してください。
> 今回は社内通知もLINEなので不要です。

登録したら **Deploys** → **Trigger deploy** → **Deploy site** で公開しなおします。
緑色の **Published** が出れば成功です。

> ⚠️ **1回目のデプロイが赤く失敗しても正常です**
>
> 環境変数を入れる前にデプロイが始まると、台帳に接続できず必ず失敗します。
> **これは異常ではありません。** 環境変数を登録してから公開しなおせば成功します。
>
> なお、台帳の中身（表の作成）はデプロイのたびに自動で行われます。手作業は必要ありません。

### 最後に7つ目を登録する

公開に成功すると `https://なにか.netlify.app` というURLが決まります。
これを `APP_BASE_URL` という名前で環境変数に追加し、もう一度デプロイしなおしてください。
通知に「該当のお客様ページへのリンク」が載るようになります。

## 06. LINEと繋ぐ（LINE Developers / 5分）

1. LINE Developers の **Messaging API設定** に戻る
2. **Webhook URL** に、手順05のURLの後ろに `/api/line/webhook` を付けたものを入力
3. **更新** → **検証** ボタンを押す
4. **成功** と出れば繋がりました

```
# 入力する形
https://あなたのサイト名.netlify.app/api/line/webhook
```

**「検証」が失敗するとき**
- URLの綴りを確認（`/api/line/webhook` まで入っているか）
- 「Webhookの利用」がオンになっているか
- Netlifyのデプロイが **Published** になっているか

## 07. 初期データを入れる（パソコン作業 / 20分・1回だけ）

> ⚠️ **ここだけブラウザで完結しません**
>
> 管理画面にログインするための最初のアカウントを作る作業です。
> **初回に1度だけ**必要で、以降は二度と行いません。
> パソコンでの操作に不安がある場合は、この作業だけ詳しい方に頼むのが確実です。

### 準備

1. https://nodejs.org/ja から **LTS版** をダウンロードして入れる
2. https://git-scm.com/downloads から Git を入れる
3. 「ターミナル」を開く
   - Mac：アプリケーション → ユーティリティ → ターミナル
   - Windows：スタートメニューで「PowerShell」と検索

### 実行する

次の内容を1行ずつ貼り付けて、そのつどEnterを押します。

```bash
# 1. プログラムを手元にコピーする
git clone https://github.com/dfestate2-jpg/threads-auto-post.git
cd threads-auto-post

# 2. 必要な部品を取り込む（数分かかります）
npm install

# 3. 台帳の場所と、管理者アカウントを指定する
#    " " の中はご自身の値に置き換えてください
export DATABASE_URL="手順02の接続文字列（Transaction pooler / 6543）"
export DIRECT_URL="手順02の接続文字列（Session pooler / 5432）"
export SEED_ADMIN_EMAIL="あなたのメールアドレス"
export SEED_ADMIN_PASSWORD="英数字を混ぜた10文字以上"

# 4. 初期データを入れる
npm run seed
```

最後に `seed 完了` と表示されれば成功です。
設定・エスカレーションの初期値・2026年の祝日・Slackの通知先・管理者アカウントが登録されます。

**Windowsの場合** — PowerShellでは `export` が使えません。次のように書き換えてください。

```powershell
$env:DATABASE_URL="手順02の接続文字列（Transaction pooler / 6543）"
$env:DIRECT_URL="手順02の接続文字列（Session pooler / 5432）"
$env:SEED_ADMIN_EMAIL="あなたのメールアドレス"
$env:SEED_ADMIN_PASSWORD="英数字を混ぜた10文字以上"
```

> **このパソコン作業をなくすこともできます**
> ブラウザだけで最初の管理者を登録できる「初回セットアップ画面」を追加できます。
> そうすればこの手順07が丸ごと不要になります。

## 08. 管理画面を整える（ブラウザ / 15分）

手順05のURLをブラウザで開き、手順07で決めたメールアドレスとパスワードでログインします。
**ログインできたら、まずパスワードを変更してください。**

1. **設定 → 担当者** — 社員の名前を登録。責任者を設定すると、時間が経ったとき責任者にも通知が行きます
2. **設定 → 通知チャネル → テスト送信** — Slackに届くことを確認。**全員のスマホに通知が鳴るか、この場で確かめてください**
3. **設定 → 営業時間** — 初期値は月〜土 9:00〜20:00、日曜休み。実態に合わせて変更
4. **設定 → エスカレーション** — 初期値は 1時間→担当者 / 3時間→担当者と責任者 / 6時間→管理者。そのままで問題ありません
5. **未返信一覧** — お客様が現れたら、一人ずつ担当者を割り当てます

> 担当者を割り当てていないお客様も、通知が消えることはありません。
> 担当者未設定の場合は社内共通のSlackチャンネルに通知されます。

## 09. 見張り番を置く（UptimeRobot / 10分）

> 🛑 **省略しないでください**
>
> 5分おきの見回り（Cron）が止まると、通知が完全に出なくなります。
> しかも**止まったことに誰も気づけません**。
> これがこのシステムで唯一、静かに壊れうる箇所です。外から見張りを置いて防ぎます。

1. https://uptimerobot.com/ で無料登録
2. **Add New Monitor**
3. Monitor Type：**HTTP(s)**
4. URL：手順05のURLの後ろに `/api/health` を付けたもの
5. Monitoring Interval：**5分**
6. 通知先に自分のメールアドレスを設定して保存

このページは、見回りが20分以上止まっている場合や、30分以上放置されている未返信がある場合に
エラーを返します。**UptimeRobotからメールが来たら、システム側の異常です。**

管理画面のダッシュボード上部にも、同じ条件で赤い警告帯が出ます。

## 10. 社内に伝える（5分）

担当者に伝えることは、実質1つだけです。

> **お客様への返信は、必ず管理画面から送ってください。**

管理画面から送れば、LINEへの送信と「対応済み」への切り替えが同時に行われ、
リマインドが確実に止まります。

### なぜこのルールが必要か

LINEの仕様上、**LINE公式アカウントManagerのチャット画面から送った返信は、システム側から見えません。**
これはLINE側の制限で、プログラムでは回避できません。

そのため、LINE公式Manager から返信してしまった場合は、管理画面の
**「LINE公式Managerで返信済み → 対応済みにする」** ボタンを押す必要があります。
押し忘れると通知が鳴り続けますが、**見落とすことはありません**。
黙って止まるより鳴り続けるほうが安全だ、という考えで作ってあります。

# ちゃんと動くか自分で試す（15分）

本番のお客様で試す前に、自分のLINEで一通り確認してください。

1. 自分のスマホから、御社の公式LINEを友だち追加する
2. 「テストです」とメッセージを送る
3. 管理画面の **未返信一覧** に、自分が数秒〜1分以内に出てくるか確認
   - 出てこない → 手順06のWebhook設定を見直す
4. 設定画面で「初回リマインドまでの時間」を一時的に5分にして試す
5. Slackに通知が届き、**スマホが鳴る**ことを確認
6. 管理画面から返信を送り、**通知が止まる**ことを確認
7. 試した設定を元に戻す（初回リマインドは60分）

> 🛑 **5番を飛ばさないでください**
> 「Slackの画面には届いていたが、スマホは鳴っていなかった」が最も多い失敗です。
> 手順03で説明した通知設定（すべてのメッセージ）を、担当者全員分ここで確認してください。

# 毎日の使い方

**担当者** — Slackに通知が来たら管理画面を開き、該当のお客様に返信する。それだけです。

**管理者（1日1回）**
- [ ] ダッシュボードの「24時間以上未返信」が 0 か
- [ ] 「要確認」が 0 か（0でなければ何かが失敗しています）
- [ ] 赤い警告帯が出ていないか

**ときどき**

| 時期 | やること |
|------|---------|
| 毎月 | LINEのメッセージ通数を確認（プラン超過していないか） |
| 毎年12月 | 翌年の祝日を「設定 → 祝日・臨時休業日」に登録 |
| 半年ごと | LINEアクセストークンとSlack Webhook URLを再発行して入れ替え |

# 困ったとき

| 症状 | 確認する順番 |
|------|-------------|
| お客様のメッセージが一覧に出てこない | ① LINE DevelopersのWebhook URLが正しいか ② 「Webhookの利用」がオンか ③ Netlifyのデプロイが Published か |
| 通知が来ない | ① 設定 → 通知チャネルでテスト送信 ② Slackチャンネルの通知が「すべてのメッセージ」か ③ そのお客様の間隔が「通知しない」になっていないか ④ 営業時間外ではないか ⑤ 顧客詳細の「リマインド送信履歴」に失敗が出ていないか |
| 返信したのに通知が続く | LINE公式Managerから返信した可能性。管理画面の「対応済みにする」を押す |
| 通知が多すぎる | 設定 → 既定のリマインド間隔を2時間または3時間に変更 |
| 「要確認」が増えた | 送信が3回失敗した／通知先が見つからない／お客様にブロックされた。顧客詳細の送信履歴に理由が残っています |
| ログインできない | 5回間違えると15分ロックされます。15分待って再度お試しください |
| UptimeRobotからエラーメールが来た | Netlifyの **Deploys** と **Functions** のログを確認 |

より詳しい資料は `docs` フォルダにあります。とくに
[`06-operations.md`](./06-operations.md)（運用手順）と
[`07-line-reply-detection.md`](./07-line-reply-detection.md)（LINEの制限と対策）が
困ったときの参照先として役立ちます。
