# 10. 銀行入金 → Googleスプレッドシート 自動反映

> 会社の銀行口座（ドコモの銀行＝ドコモSMTBネット銀行）への入金を自動取得し、
> 既存の入金管理スプレッドシートへ **入金日 / 入金者 / 入金額** を重複なく積み上げる。
>
> 実装は **Google Apps Script**。コードと導入手順は [`gas/`](../gas/README.md)。
> 本ドキュメントは「なぜこの方式にしたか」と、費用・セキュリティ・運用をまとめたもの。

---

## 0. 調査結果 — どの経路で明細を取るか

### 0-1. 「ドコモ銀行」の特定

住信SBIネット銀行は **2026年8月3日に「ドコモSMTBネット銀行」へ商号変更**された（ドコモの銀行）。
金融機関コード・支店番号・支店名・口座番号に変更はなく、旧行名での振込受付は2026年10月30日まで。
2025年10月1日にNTTドコモの連結子会社となり、ドコモと三井住友信託銀行の共同経営体制になったことに伴う変更。

### 0-2. 取得方式の比較

| # | 方式 | 実現性 | 追加費用 | 規約 | 判定 |
|---|------|--------|----------|------|------|
| ① | 銀行の参照系API（残高・入出金明細照会）を自社が直接叩く | **×** | — | — | 銀行のAPI接続サービスは、**電子決済等代行業者として登録した提携先企業向け**の枠組み。一般の事業会社が単独でAPIキーの発行を受ける窓口は公開されていない |
| ② | **freee会計の口座同期 ＋ freee Public API** | **◎** | **¥0** | 公式API | **採用** |
| ③ | マネーフォワード クラウド ＋ MF API | ○ | 別契約が必要 | 公式API | freee を既に使っており二重契約になる |
| ④ | 全銀フォーマットの入出金明細伝送 / 明細CSVの手動ダウンロード | △ | 銀行の伝送サービス料 | 公式 | 「自動で取得する」部分を別途作り込む必要があり、人手が残る |
| ⑤ | ネットバンキングのスクレイピング | **×** | — | **規約違反の恐れ** | 依頼どおり採用しない |

### 0-3. ② を採用した理由

- **銀行のログイン情報をこのシステムが一切持たない。**
  銀行に接続するのは freee 側だけ。スクリプトは freee のAPIを読むだけ。
- **追加費用が発生しない。** freee は既に契約済みで、freee Public API・Apps Script はいずれも無料。
- **会計と数字が二重管理にならない。** 経理が見ている明細と同じものをシートに載せる。
- **既に同じ方式が社内で動いている。**
  「振込自動記入（出金版）」が freee → スプレッドシートで稼働中。
  入金版はその姉妹スクリプトとして作られており、運用も同じ。
- **取得方式を後から変えてもスクリプトは動く。**
  freee 側の同期方式（API連携 / 明細アップロード）が変わっても、
  読み出す口座明細（wallet_txns）の形は同じ。

### 0-4. なぜ Apps Script なのか

| 理由 | 内容 |
|------|------|
| 既存運用と同じ | 出金版が Apps Script で稼働中。**仕組みを2つの流儀で持たない** |
| インフラを増やさない | サーバー・DB・デプロイが不要。スプレッドシートの隣で完結する |
| 触れる人が多い | Apps Script のエディタで開いて直せる。設定変更にデプロイが要らない |
| 権限が閉じている | スクリプトを所有する Google アカウントの権限だけで動く。サービスアカウントの鍵を配らなくてよい |

### 0-5. この経路の制約（把握しておくこと）

| 制約 | 内容 | 対応 |
|------|------|------|
| リアルタイムではない | freee の銀行同期は1日数回。着金からfreeeへの反映まで数時間〜1日 | 取り込みは4時間ごと。**当日中〜翌営業日に載る** |
| 入金者名は銀行が送る摘要そのまま | `ﾌﾘｺﾐ ｶ)ﾀﾏﾎｰﾑ` のような半角カナ。契約者名とは限らない | スクリプト側で整形する（後述）。契約者名（B列）は従来どおり人が入れる |
| 連携が切れても静かに止まる | freee側の口座連携が切れると、**エラーは出ないのに明細だけが来なくなる** | `入金が途絶えていないか見張る` を毎日実行してメールで検知する |
| Apps Script の実行時間上限 | 1回6分 | 30日分でも数十件のため問題にならない |

## 4. システム構成

```
  ┌─────────────────────────┐
  │ ドコモSMTBネット銀行      │  会社の法人口座に入金が発生
  │ （旧 住信SBIネット銀行）   │
  └────────────┬────────────┘
               │ 銀行 ⇄ freee の口座同期（1日数回）
               │ ※ スクリプトは銀行のIDもパスワードも持たない
               ▼
  ┌─────────────────────────┐
  │ freee 会計              │  「自動で経理」の口座明細として蓄積
  └────────────┬────────────┘
               │ freee Public API
               │ GET /api/1/wallet_txns?entry_side=income
               ▼
  ┌──────────────────────────────────────────────────┐
  │ Google Apps Script「入金自動記入」                   │
  │                                                  │
  │  4時間ごと ─▶ 入金を取り込む()                      │
  │                 ├─① 入金だけ取得（過去30日分）       │
  │                 ├─② 摘要 → 入金者名に整形           │
  │                 ├─③ _sync_入金 と突合  ★重複防止    │
  │                 └─④ 未登録分だけ月次シートへ追記      │
  │                                                  │
  │  毎日1回 ──▶ 入金が途絶えていないか見張る()          │
  │                 └─ 明細が5日届かなければメール        │
  └────────────┬─────────────────────────────────────┘
               │ SpreadsheetApp
               ▼
  ┌─────────────────────────────────────────────┐
  │ 既存スプレッドシート                            │
  │   シート名 = 入金月（2026/08 …）                │
  │   2行目: 見出し / 3行目〜: データ                │
  │   入金日 / 契約者名 / 入金者 / 入金額 /          │
  │   契約締結日 / 備考                             │
  │   ↑ 書くのは入金日・入金者・入金額の3列だけ。     │
  │     列位置は見出しの文字から毎回探す              │
  └─────────────────────────────────────────────┘
```

### 4-1. 既存シートの運用に合わせている点

| 既存の運用 | スクリプトの動作 |
|-----------|-----------------|
| 月ごとにシートを分け、名前は `yyyy/MM`（例 `2026/08`） | 入金日の月のシートへ書く。**既にあればそこへ追記**し、無いときだけ「コピー」を複製して作る。探すときは `2026/9` `202609` `2026年9月` なども同じ月とみなす |
| 見出しは2行目、データは3行目から | 3行目以降の末尾に追記 |
| 見出し行（2行目）に 入金日 / 契約者名 / 入金者 / 入金額 / 契約締結日 / 備考 が並ぶ | **入金日・入金者・入金額の3列のみ**書き込む。列番号は見出しの文字から自動判定するため、列が足されてもずれない。契約者名・契約締結日・備考は人が埋める |
| 同じ入金日が続くとき、2行目以降のA列は空欄 | 同じ挙動 |
| 入金者はカタカナの振込人名義（`タマホーム`, `クラハシ　ジユンヤ`） | 半角カナを全角に直し、`ﾌﾘｺﾐ` などの取引種別と法人格略号 `ｶ)` を落とす |

### 4-2. 出金版（振込自動記入）との関係

| | 振込自動記入 | 入金自動記入 |
|---|---|---|
| 対象 | 支払った記録（`entry_side=expense`） | 受け取った記録（`entry_side=income`） |
| ブック | 振込管理ブック | 入金管理ブック |
| Apps Script プロジェクト | 既存 | **別プロジェクト**（理由は下記） |

**必ず別プロジェクトにすること。**

1. `トリガー登録` はプロジェクト内のトリガーを全消しして作り直すため、同居させると相手のトリガーが消える
2. `FREEE_REFRESH_TOKEN` は**使い捨て**。同じ値を2つのスクリプトで共有すると、
   片方が更新した瞬間にもう片方が認証エラーになる
   → 各プロジェクトで `step1` / `step2` を実行し、**専用のトークンを取る**

## 5. 実装手順

導入手順は [`gas/README.md`](../gas/README.md) を参照。要点だけ挙げると：

1. freee 会計で対象口座の同期を設定する（可能なら **API連携方式**）
2. 新しい Apps Script プロジェクトを作り、`gas/入金自動記入.gs` を貼る
3. スクリプトプロパティを設定する（`FREEE_*` / `SS_ID` / `ALERT_MAIL`）
4. `step1_認可URL表示` → `step2_認可コード登録` で freee を認可する
5. **`設定.取り込み開始日` を「手入力済みの最後の入金日の翌日」にする**
6. `状況を確認する` で、書かれる予定の明細を確認する（書き込みはしない）
7. `入金を取り込む` を手動で1回 → 問題なければ `トリガー登録`

## 6. セキュリティ上の注意点

| # | 論点 | 対応 |
|---|------|------|
| 1 | **銀行の認証情報** | **一切保持しない。** 銀行に接続するのは freee であり、スクリプトは freee のAPIを読むだけ。銀行のID・パスワードを書く場所が存在しない |
| 2 | **スクレイピングをしない** | 銀行サイトへのアクセスは1行も無い。取得は freee の公開APIのみ |
| 3 | **銀行側の権限** | 連携に使う銀行の利用者は **照会のみ**。振込・払戻の権限を与えない |
| 4 | **freee のトークン** | `client_secret` とリフレッシュトークンはスクリプトプロパティに置き、コードに直書きしない。リフレッシュトークンは使い捨てのため、更新後の値を即保存する。アクセストークンは `CacheService` に有効期限つきで置く |
| 5 | **多重起動** | `LockService` で直列化。トークンの二重更新（＝失効）を防ぐ |
| 6 | **書き込み範囲の限定** | 書くのは A・C・D 列だけ。人が入力する B・E・F 列と、他のシートには触らない |
| 7 | **暴走時の被害限定** | `取り込み開始日` より前の明細は取り込まない。ページングにも上限（3000件）がある |
| 8 | **共有範囲** | スクリプトはブックを編集できる Google アカウントの権限で動く。ブックの共有範囲を必要な担当者に限定すること |
| 9 | **個人情報** | 振込人名義は個人情報にあたる。ブックの閲覧権限を絞る |

## 7. 重複登録を防ぐ仕組み（依頼の要件③）

| 段 | 仕組み | 防いでいる事故 |
|---|--------|---------------|
| ① | `_sync_入金` シートに freee の明細ID を記録し、同じIDは二度書かない | 30日さかのぼって毎回取得しても、同じ入金は1回しか書かれない |
| ② | 書き込めた分のIDを **`finally` で必ず保存する** | 途中で失敗しても、書けた行が次回に再度書かれない |
| ③ | `LockService` による多重起動の防止 | トリガーが重なっても同時に走らない |
| ④ | `取り込み開始日` より前は取り込まない | **導入前に手入力済みの行**と重複しない |

### ② について（出金版にあった不具合）

出金版は、追記ループが**全部終わってから**IDを保存している。

```js
明細.forEach(m => { 月シートに追記_(m); 済み.add(m.id); 件数++; });
if (件数 > 0) 処理済みID保存_(済み);   // ← ここまで来ないと保存されない
```

途中の1件で例外が出ると保存されないまま終わるため、
**次回の実行で「すでに書けていた行」がもう一度書かれる**。

入金版は保存を `finally` に移してこれを塞いでいる。
**振込版にも同じ1行の修正を入れることを推奨する。**

## 8. 運用とトラブルシューティング

### 確認に使う関数

| 関数 | 用途 |
|------|------|
| `状況を確認する` | 書き込み先・登録済みID数・新規件数・対象明細を一覧表示（**書き込まない**） |
| `摘要を確認する` | 摘要 → 入金者名 の変換結果を一覧表示。除外設定を決めるときに使う |
| `どの口座か調べる` | どの口座に入金明細が入っているかを調べる |
| `記入をやり直す` | `_sync_入金` を空にして取り込み直す（シートの既存行は消えない） |

### よくある失敗と対処

| 症状 | 原因 | 対処 |
|------|------|------|
| `トークン更新失敗` | リフレッシュトークンが失効（長期間未使用／出金版とトークンを共有している） | `step1` → `step2` で再認可する。**出金版と別のトークンにする** |
| `スクリプトプロパティ未設定: XXX` | プロパティの登録漏れ | ［プロジェクトの設定］＞［スクリプト プロパティ］を確認 |
| 入金がシートに出てこない | freee 側にまだ明細が来ていない | freee の［自動で経理］を確認。銀行同期は1日数回 |
| 過去の入金が大量に追記された | `取り込み開始日` が古い | 設定を直し、余分な行を手で消してから `記入をやり直す` |
| 見出しが見つかりませんとエラーが出る | 見出しの文字が変わった | `設定.見出し` を実際の文字に合わせる。**列がずれたまま書かないための安全装置**なので、無視して決め打ちに戻さないこと |
| 同じ月のシートが複数あります、とエラーが出る | 表記の違う同月シートが並存している（例 `2026/09` と `202609`） | 1つに整理してから再実行する。**どちらに書くか決められないので勝手に選ばない**仕様 |
| 入金者名が読みにくい | 摘要の形が想定外 | `摘要を確認する` で実際の摘要を見て、`入金者名を整形_` の除去パターンを足す |
| 記入したくない入金がある | ポイント利用・利息など | `設定.除外_含む` にその言葉を足す。半角カナ・全角の違いは自動で吸収する。会社名に同じ言葉が入って巻き込まれる場合は `設定.除外_先頭` へ移す |
| 明細が途中の日付で止まっている | freee 側の同期がその日で止まっている | freee の［口座］画面で最終同期日時を確認し、同期または再連携する。**スクリプト側の設定では直らない** |
| 「明細が届いていません」メール | freee の口座連携が切れた | freee の［口座］画面で再連携する |

### 月が替わったとき

新しい月のシートは、最初の入金が発生した時点で **「コピー」シートの複製として自動作成**される。
人の作業は不要。

## 9. 将来、銀行の参照系APIを直接使えるようになったら

差し替えるのは `freeeから入金を取得_()` だけ。
返す形（`{ id, date, name, amount }`）に合わせれば、
重複防止・シート追記・自動実行の仕組みはそのまま使える。
