# 12. 自動追客管理システム — 起動と操作方法

## 1. 手元で動かす

PostgreSQL（16以上）と Node.js 22 が必要。

```bash
# 1. 依存パッケージ
npm install

# 2. 環境変数
cp .env.example .env
```

`.env` に最低限これだけ入っていれば、追客管理は動く（LINE連携なしでも動く）。

```
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/followup
DIRECT_URL=postgresql://postgres:postgres@localhost:5432/followup
SESSION_SECRET=32文字以上のランダムな文字列
CRON_SECRET=別のランダムな文字列
```

```bash
# 3. データベースを作る
npx prisma migrate deploy

# 4. 初期データ（追客ルール・LINEテンプレート・管理者ユーザー）
SEED_ADMIN_PASSWORD='任意のパスワード' SEED_ADMIN_EMAIL='admin@example.com' npm run seed

# 5. 動作確認用のデモ顧客（本番では実行しない）
npm run seed:demo

# 6. 起動
npm run dev     # http://localhost:3000
```

`admin@example.com` と設定したパスワードでログインする。
管理者ユーザーは `/setup` からブラウザだけで作ることもできる。

### 動作確認

```bash
npm test                    # 判定ロジックのユニットテスト（167ケース）
npm run typecheck
npm run build
npm run check:followup      # 実DBに対する追客の結合確認（39項目）
npm run check:reminder      # 実DBに対する未返信リマインドの結合確認
npm run followups:run       # 追客の定期実行を手元で1回だけ走らせる
```

## 2. 営業担当の使い方

### ログインしたら「今日やること」だけ見る

トップ画面には、対応が必要な顧客だけが上から順に並ぶ。

```
🔴 期限超過   6件   ← まずここ
🔴 最優先     4件   ← 今日中に
🟡 通常       1件
🟢 自動追客中 6名   ← 何もしなくてよい。期限が来たら勝手に出てくる
```

各行には「誰に・なぜ・何をするか」が1行で書いてある。

```
S  青木 健一  2日超過   見積書待ち 3日  →  💬 LINE  見積書の進捗連絡   期限 8/28   [LINEを送る] [対応した]
```

### 対応したら押すボタンは1つ

| したこと | 押すもの |
|---------|---------|
| 電話した・LINEした | 行の **「対応した」** |
| LINEを送りたい | **「LINEを送る」**（候補文が出る。選んで送信） |
| 電話したい | **「電話をかける」**（スマホならそのまま発信） |

押すと、最終接触日時・次回追客日・優先度・追客履歴がすべて自動で更新される。
**次回いつ追客するかを考える必要はない。**

### 顧客画面のボタン

進捗が動いたときは顧客画面のボタンを押す。押した内容がそのままステータスになる。

| ボタン | 顧客ステータス |
|--------|--------------|
| 🏠 物件を提案 | 物件提案中（2日後・5日後・10日後に追客が立つ） |
| 🧾 見積書を依頼 | 見積書待ち（24時間後・48時間後・72時間後） |
| 🚗 内見を設定 | 内見調整中 |
| ✅ 内見が終わった | 内見済（当日・2日後・5日後にフォロー） |
| 📝 申込検討へ / 📄 申込を受けた | 申込検討 / 申込済 |
| 🎉 成約 / ❌ 失注 | 追客終了 |
| ⏸ 保留 / 💤 休眠 | 追客の間隔を空ける |

### LINEの文章は考えなくてよい

「LINEを送る」を押すと、その顧客の**今の状況に合った候補文**が出る。
顧客名・担当者名・希望エリア・希望家賃は差し込み済み。そのまま送っても、直してから送ってもよい。

手元のLINEアプリから送った場合は **「送信済みとして記録」** を押す。追客履歴に残り、次回追客日が進む。

### 放っておいても追客は止まらない

- 返信が来ない顧客は、1日後 → 3日後 → 7日後（電話）→ 14日後 → 30日後で自動的に追いかける
- 30日反応が無ければ「休眠」に移り、通算60日・90日で掘り起こしのLINEが立つ
- **顧客からLINEが届いたら、休眠からでも自動で復活し、最優先（S）で今日の画面に出る**

## 3. 管理者の使い方

`/admin` で全体を見る。

- 🔴 期限超過 / 今日の追客対象 / 本日の追客実施数 / 担当者未設定
- 追客中・自動追客中・返信なし・休眠・成約・失注の件数
- 担当者別の 反響 / 追客回数 / 対応顧客 / 内見 / 申込 / 成約 / 成約率 / 期限超過

数字は追客履歴（`follow_up_logs`）から作られるため、営業担当の自己申告に依存しない。
期限超過が特定の担当者に偏っていれば、その時点で分かる。

### 追客ルールを会社に合わせる

`/settings/followup` で、ステータスごとの「何分後に何をするか」を変更できる。
変更は、以降に計算される次回アクションから反映される。

LINEテンプレートも同じ画面で編集する。

## 4. 本番運用

### 定期実行

| ジョブ | 間隔 | 役割 |
|--------|------|------|
| `/api/cron/reminders` | 5分ごと | 未返信リマインド |
| `/api/cron/followups` | 1時間ごと | 追客の自動遷移・営業への通知・優先度の引き直し |

Netlify では `netlify/functions/followups-cron.mts`、Vercel では `vercel.json` の `crons` が
それぞれ設定済み。認証は `x-cron-secret: $CRON_SECRET`。

```bash
curl -X POST https://<host>/api/cron/followups -H "x-cron-secret: $CRON_SECRET"
```

### 公式LINE・Lステップとの役割分担

| | 役割 |
|---|---|
| 公式LINE | 顧客とのやり取り |
| Lステップ | タグ・シナリオ・自動返信・アンケート |
| このシステム | 顧客管理・担当管理・追客管理・次回アクション・今日やること・営業分析 |

LINE の Webhook（`/api/line/webhook`）と Lステップからの転送（`/api/line/relay`）は既に受け口があり、
顧客からの受信・担当者からの送信が、そのまま追客の状態更新につながる。設定手順は [docs/06](06-operations.md) と [docs/08](08-lstep-coexistence.md) を参照。

## 5. よくある確認

**Q. 顧客が今日の画面に出てこない**
次回アクション日時がまだ先（＝自動追客中）か、成約・失注か、自動追客をオフにしている。
顧客画面の「次回アクション」欄で期限を確認する。

**Q. 追客ルールを使い切った顧客はどうなる**
今日の画面の「⚪️ 追客ルール終了（要判断）」に出続ける。保留・失注などを選ぶまで消えない。

**Q. ステータスを間違えた**
顧客画面の「ステータスを手動で変更」で直せる。変更した時点から、そのステータスの追客リズムが始まる。

**Q. この顧客だけ自動追客を止めたい**
顧客画面の「自動追客の対象にする」のチェックを外す。今日の画面に出なくなる。
