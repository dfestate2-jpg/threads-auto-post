# 08. 物件情報の一斉メール配信

公式LINEの一斉配信で反応が取れなかった層に、メールで物件情報を届けるための機能。

> **この機能の前提**
> 送信先は「SNS広告 → 公式LINE → フォーム回答」で自社が取得した見込み客リスト。
> 購入リスト・収集リストへの送信は想定していないし、法令上できない。

---

## 1. 送る前に必ず読むこと

### 1-1. 法律（特定電子メール法）

物件情報のメールは「広告・宣伝メール」に当たるため、以下が義務。

| 義務 | 本システムでの対応 |
|------|-------------------|
| 原則オプトイン（事前同意） | `Contact.consent` で管理。既定の配信対象は `OPTED_IN` のみ |
| 同意の記録の保存 | `consentAt`（同意日時）・`consentNote`（取得経路）・`source` に保存 |
| 送信者の氏名/名称・住所の表示 | `MAIL_SENDER_ORG` / `MAIL_SENDER_ADDRESS` を**本文末尾に自動付与**。担当者は消せない |
| 配信停止の方法の表示と、その受付 | 配信停止URLを全メールに自動付与。`/api/unsubscribe` が受け付ける |

**「同意あり」として扱ってよいのはどんな場合か**

フォームに「物件情報をメールでお送りします」等の記載があり、それを承知で
メールアドレスを入力してもらった場合。この場合は取込時に
「このリストは配信同意を得ている」にチェックを入れる。

記載が無かった場合は、チェックを入れずに「同意不明」として取り込む。
同意不明の人は既定の配信対象に入らない。送る場合は、配信作成画面で
「配信同意が確認できている人だけに送る」のチェックを外す判断を、
取得経路を説明できる状態で行うこと。

> フォームに配信同意の記載が無かった場合、今後のフォームには必ず入れておく。
> 過去分は「同意不明」のまま運用するのが安全。

### 1-2. 技術（Gmail / Yahoo の一括送信者要件）

2024年以降、1日5,000通以上を送る送信者には次が必須。3,000件規模でも
準拠していないと迷惑メール送りにされるため、最初から満たしておく。

| 要件 | 対応 |
|------|------|
| SPF・DKIM・DMARC の設定 | **送信ドメイン側の作業。これだけは自分でやる必要がある**（後述） |
| ワンクリック配信停止 | `List-Unsubscribe` / `List-Unsubscribe-Post` ヘッダを全メールに付与済み |
| 迷惑メール報告率 0.3% 未満 | バウンス・苦情 Webhook で自動的に配信停止台帳へ登録 |
| 1通1宛先 | キューで1件ずつ送信。BCC 一括送信はしない |

⚠️ **自社サーバーのSMTPから直接送らないこと。** 3,000通を自前で送ると
IPレピュテーションが落ち、見積書や契約書など通常の業務メールまで届かなくなる。

## 2. セットアップ

### 2-1. 送信ドメインの認証（最初に、必ず）

1. 送信プロバイダ（Resend または SendGrid）に登録し、送信ドメインを追加する
2. プロバイダが提示する DNS レコード（SPF / DKIM）を、ドメインの DNS に登録する
3. DMARC レコードを登録する。最初は監視のみで始める:

   ```
   _dmarc.example.co.jp  TXT  "v=DMARC1; p=none; rua=mailto:dmarc@example.co.jp"
   ```

4. プロバイダの管理画面で認証が「Verified」になるまで待つ

**この作業を飛ばして配信を始めないこと。** 到達率が回復不能なほど落ちる。

### 2-2. 環境変数

`.env.example` の「物件情報の一斉メール配信」以下を設定する。

```bash
MAIL_PROVIDER="resend"                    # resend / sendgrid
MAIL_API_KEY="re_xxxxx"
MAIL_FROM_ADDRESS="info@example.co.jp"    # 2-1 で認証したドメイン
MAIL_FROM_NAME="〇〇不動産"
MAIL_SENDER_ORG="株式会社〇〇不動産"       # 法定表示
MAIL_SENDER_ADDRESS="東京都〇〇区..."      # 法定表示
MAIL_SENDER_TEL="03-1234-5678"
UNSUBSCRIBE_SECRET="$(openssl rand -hex 32)"
MAIL_WEBHOOK_SECRET="$(openssl rand -hex 32)"
```

`MAIL_SENDER_ORG` / `MAIL_SENDER_ADDRESS` が未設定だと、配信開始時に
エラーになって送信できない（法定表示の無いメールを送らせないため）。

`MAIL_PROVIDER` を空にしておくと「動作確認モード」になる。配信フローは
最後まで動くがメールは飛ばないので、本番の鍵を入れる前の確認に使える。

### 2-3. バウンス通知の Webhook

プロバイダの管理画面で、次のURLを Webhook として登録する。

```
https://<あなたのホスト>/api/email/webhook?token=<MAIL_WEBHOOK_SECRET>
```

- Resend: Webhooks → `email.bounced` / `email.complained`
- SendGrid: Settings → Mail Settings → Event Webhook → Bounced / Spam Reports / Dropped

これを繋がないと、宛先不明のアドレスに送り続けて到達率が落ちる。

### 2-4. 定期実行

配信キューの消化は `/api/cron/campaign` を**1分ごと**に叩くことで進む。

- Vercel: `vercel.json` に設定済み
- Netlify: `netlify/functions/campaign-cron.mts` に設定済み
- その他: `curl -X POST -H "x-cron-secret: $CRON_SECRET" https://<host>/api/cron/campaign`

1回あたり `MAIL_BATCH_SIZE` 件（既定100件）を送るので、既定設定で
**1時間あたり約6,000通**。3,000件のリストは約30分で送り切る。

## 3. 運用手順

### 3-1. リストを取り込む

`配信先リスト` 画面 → CSV を選択（またはテキスト欄に貼り付け）。

**認識する列名**（表記揺れは吸収する。大文字小文字・全角半角・スペースは無視）

| 意味 | 認識する見出し |
|------|---------------|
| メールアドレス（必須） | メールアドレス / メール / メアド / email / mail |
| 名前 | 名前 / 氏名 / お名前 / 顧客名 / name |
| フリガナ | カナ / フリガナ / kana |
| 電話番号 | 電話番号 / 電話 / 携帯 / tel / phone |
| 希望エリア | 希望エリア / エリア / 地域 / area |
| 予算 | 予算 / ご予算 / 予算上限 / budget |
| 物件種別 | 物件種別 / 種別 / 希望種別 / type |
| 配信同意 | 配信同意 / 同意 / consent / optin |
| 登録日時 | 登録日時 / タイムスタンプ / 回答日時 |

予算は「5000万」「5,000万円」「1億2000万」「50000000」いずれも万円に正規化される。

**必ず「内容を確認（取り込まない）」を先に押す。** 認識した列と、読み取れた
最初の10件が表示されるので、意図どおりか確認してから取り込む。

### 3-2. 物件を登録する

`POST /api/properties` で登録する（管理画面は未実装。当面はAPI経由）。

```bash
curl -X POST https://<host>/api/properties \
  -H "Content-Type: application/json" \
  -H "Cookie: <ログイン後のCookie>" \
  -d '{"title":"世田谷区 中古マンション","propertyType":"MANSION","area":"世田谷区","price":5480,"layout":"3LDK","stationAccess":"三軒茶屋駅 徒歩7分","url":"https://..."}'
```

### 3-3. 配信を作る

`一斉配信` → `新しい配信を作成`

**本文の差し込み変数**

| 変数 | 展開されるもの |
|------|---------------|
| `{{name}}` | お客様の名前。未登録なら「お客」（`{{name}}様` → `お客様`） |
| `{{properties}}` | 選んだ物件の一覧（テキスト版とHTML版の両方を自動生成） |
| `{{unsubscribe_url}}` | 配信停止リンク（書かなくても末尾に自動で付く） |

会社名・住所・配信停止リンクは本文に書かなくても自動で付く。消せない。

**配信対象の設定**

| 設定 | 意味 |
|------|------|
| 配信同意が確認できている人だけに送る | 既定ON。外すと「同意不明」の人にも送る |
| **公式LINEで反応が無い人だけに送る** | LINEブロック済み・LINEに居ない・指定日数こちらへの発信が無い人だけに絞る |
| 希望エリア / 価格帯 | 登録済みの希望条件で絞る。**未登録の人は除外しない**（取りこぼし防止） |

「公式LINEで反応が無い人だけに送る」は、LINE一斉配信と二重に届くのを
防ぐための条件。LINEで既に反応している人にメールを重ねると鬱陶しがられる。

### 3-4. 送る

1. **「自分にテスト送信」** — 必ず先に押す。迷惑メール判定・文字化け・
   差し込みミスを自分の受信箱で確認する。スマホでも見ること。
2. **「対象と文面を確認」** — 何件に届くか、実際の文面がどうなるかが出る
3. **「この内容で N件に配信を開始する」** — 確認ダイアログの後、キューに登録

送信は Cron が1分ごとに少しずつ進める。進捗は配信詳細画面に自動更新で出る。

### 3-5. 止める

配信詳細画面の **「送信を一時停止する」**。
ただし、直前に送信処理へ入った数件（最大 `MAIL_BATCH_SIZE` 件）は届く。

## 4. 「送ってはいけない相手に送らない」仕組み

事故が最も痛いのがここなので、4段構えにしてある。

| # | 仕組み | 効くタイミング |
|---|--------|---------------|
| 1 | セグメント抽出条件（`segment.ts`）に、配信停止の除外を**常に**含める | 対象を数えるとき・確定するとき |
| 2 | 対象確定時に `suppressions`（停止台帳）を引いて除外 | 送信キューに積むとき |
| 3 | **送信直前にもう一度** `Contact` と `suppressions` を引き直す | 1通ごと |
| 4 | CSV 再取込時、停止台帳に載っている宛先は `UNSUBSCRIBED` に固定 | 取り込みのたび |

`suppressions` は `Contact` とは別テーブルなので、**配信先を削除しても・
CSVで作り直しても、配信停止した人が復活することはない。**

二重送信の防止は `campaign_recipients` の `(campaignId, contactId)` UNIQUE 制約。
Cron が多重起動しても、同じ人に同じ配信が2通届くことは構造的に起きない。

### 配信停止リンクの挙動

- **GET**（人がリンクを踏む） … 確認画面を出すだけ。ここでは停止しない
  - メールスキャナがリンクを自動で開くため、GET で停止すると本人の意思と
    無関係に停止されてしまう
- **POST**（確認画面のボタン、またはメールソフトの「配信停止」ボタン）… 実際に停止

`UNSUBSCRIBE_SECRET` を変更すると、**過去に送ったメールの配信停止リンクが
すべて無効になる**。法令上「いつでも停止できること」が求められるため、
この値は変更しないこと。

## 5. トラブルシューティング

| 症状 | 原因と対処 |
|------|-----------|
| 配信開始時に「MAIL_PROVIDER が未設定」 | 動作確認モードのまま。2-2 を設定する |
| 配信開始時に「環境変数 MAIL_SENDER_ORG が…」 | 法定表示の設定漏れ。2-2 を設定する |
| 確認画面に「APP_BASE_URL が未設定です」 | 配信停止リンクを作れない。`APP_BASE_URL` を設定する |
| 送信が進まない | Cron が動いていない。`/api/cron/campaign` を手動で叩いて確認する |
| 「対象件数が変わりました」で送信できない | 確認画面を出してから対象が増減した。もう一度確認し直す |
| 失敗が大量に出る | 配信詳細から `campaign_recipients.lastError` を確認。認証エラー（401/403）なら `MAIL_API_KEY`、429 なら `MAIL_CONCURRENCY` を下げる |
| 迷惑メールに入る | SPF/DKIM/DMARC の設定漏れがほぼ全て。2-1 をやり直す |

## 6. SMS について

`CampaignChannel` に `SMS` を用意し、`Contact.phone` は正規化して保存しているが、
**送信アダプタは未実装**。追加するには:

1. `src/lib/email/client.ts` と同じ形の SMS トランスポートを作る
2. `campaignRunner.ts` の `claimRecipients` から `c.channel = 'EMAIL'` の
   条件を外し、チャネルごとにトランスポートを切り替える
3. `suppressions` は `channel` 列で分けてあるので、そのまま流用できる

なお **SMS広告も特定電子メール法の規制対象**であり、同意・送信者表示・
配信停止の義務はメールと同じ。加えて1通あたり3〜10円程度の送信料がかかる。
