# 05. UI設計

管理画面は3画面。**「今すぐ返信すべき顧客が一目で分かる」**ことだけを目的に構成している。

## 共通

- 未ログインは `/login` へリダイレクト（middleware で一次判定、各ページで署名検証）
- 全ページ `noindex, nofollow`
- ダッシュボードと一覧は **60秒ごとに自動更新**（見落とし防止）
- Cron が20分以上動いていない場合、**全ページ上部に赤帯の警告**を出す

## 1. ダッシュボード `/`

```
┌──────────────────────────────────────────────────────────────┐
│ ⚠️ リマインドの定期実行が 45 分間確認できていません（異常時のみ） │
├──────────────────────────────────────────────────────────────┤
│ 🔴 未返信顧客数 │ 🟠 1時間以上 │ 🔴 3時間以上 │ 🔴 24時間以上   │
│       3         │      2       │      1       │      0        │
├──────────────────────────────────────────────────────────────┤
│ 本日のLINE受信数 │ 本日の対応済み数 │ 要確認 │ 通知OFF設定中     │
│       17        │       14        │   0    │      1           │
├─────────────────────────────────────┬────────────────────────┤
│ 長時間未返信 ワースト10               │ 担当者別の未返信件数    │
│ 顧客名／担当者／未返信経過／リマインド │ 山田            2      │
│ ／状況／受信日時                     │ 担当者未設定    1      │
│                                     │ ─────────────────────  │
│                                     │ 最終Cron実行：14:35    │
└─────────────────────────────────────┴────────────────────────┘
```

- 経過時間は **`firstUnrepliedAt` 基準**。顧客の連投でカウントが再スタートしても、
  実際に放置されている時間が見えるようにしている。
- 「通知OFF設定中」を独立したカードにしてあるのは、**意図的に通知を止めた顧客が視界から消えないようにするため**。
- 数値カードは 0 なら灰色・1以上で警告色に変わる。

## 2. 未返信一覧 `/customers`

依頼された項目をすべて列に持つ。

| 顧客名 | LINEユーザーID | 担当者 | 最終顧客メッセージ | 受信日時 | 未返信経過 | リマインド | 対応状況 | 対応済み日時 |
|--------|---------------|--------|------------------|---------|-----------|-----------|---------|-------------|

- **並び順は `firstUnrepliedAt` 昇順**（最も長く放置されている顧客が最上段）
- 未返信経過はバッジ表示で、`1時間`＝橙 / `3時間`＝赤 / `24時間`＝赤地に白抜き
- 担当者未設定は橙文字で強調
- フィルタ：フリーワード（顧客名・LINEユーザーID）、対応状況、担当者、「未返信のみ表示」
- 50件ごとのページング

## 3. 顧客詳細 `/customers/{id}`

```
田中  [未対応] [3時間20分]

┌─ メッセージ履歴 ───────────────┬─ 顧客へ返信 ─────────────────┐
│ 顧客   LINE_WEBHOOK   10:00     │ [返信内容を入力          ]   │
│ 「内見の予約をしたいのですが…」  │ [LINEへ送信して対応済みにする] │
│                                │ [LINE公式Managerで返信済み → │
│      担当者(山田) ADMIN_CONSOLE │  対応済みにする]              │
│      「ご連絡ありがとうございます」├─ 対応状況 ──────────────────┤
├─ リマインド送信履歴 ────────────┤ [未対応 ▼]                   │
│ 日時／種別／回数／未返信／結果   │ 未返信状態    未返信          │
│ ／宛先                          │ リマインド回数  3回           │
│                                │ 次回リマインド  14:00         │
│                                │ 最終受信/最終返信/対応済み日時 │
│                                ├─ 顧客情報 ──────────────────┤
│                                │ 顧客名 / LINEユーザーID       │
│                                │ 担当者 [▼] リマインド間隔 [▼] │
│                                │ メモ / [保存]                 │
└────────────────────────────────┴──────────────────────────────┘
```

### 「顧客へ返信」を最上部に置いた理由

**この画面から返信することが、返信検知の主経路**だから（[07](./07-line-reply-detection.md)）。
ここから送れば LINE への送信と「対応済み」への遷移が1操作で完結し、
「返信したのにリマインドが止まらない」も「返信していないのに止まる」も構造的に起きない。

LINE公式アカウントManager 側で返信してしまった場合のために、
すぐ下に「LINE公式Managerで返信済み → 対応済みにする」ボタンを置いている。

### リマインド間隔の個別設定

`全体設定に従う（1時間ごと）` / `1時間ごと` / `2時間ごと` / `3時間ごと` / `通知しない` から選択。
`通知しない` を選ぶと **その場で橙色の注意文を出す**（意図しない設定で見逃すのを防ぐ）。

## 4. 設定 `/settings`

5つのセクションを縦に並べた1ページ。

| セクション | 内容 |
|-----------|------|
| **基本設定** | 既定のリマインド間隔 / 初回リマインドまでの時間 / **無通知の上限** / 1サイクルの最大通知回数 / タイムゾーン / 通知本文の文字数 / 4つのトグル / **営業時間（曜日ごとに有効・開始・終了）** |
| **エスカレーション設定** | 行ごとに「ルール名・経過(分)・担当者・責任者・管理者・共通グループ・有効」。追加/削除可 |
| **担当者** | 氏名・LINEユーザーID・役割・責任者・通知ON/OFF・有効。インライン編集（blur で保存） |
| **通知チャネル** | 社内共通グループ / 管理者向け / 冗長。**チャネルごとにテスト送信ボタン**。1件も無ければ赤字で警告 |
| **祝日・臨時休業日** | 日付・名称・臨時営業日フラグ。追加/削除 |

- 「1サイクルの最大通知回数」には *0 = 無制限（推奨）。上限に達すると通知が止まる* と注意書きを添えている。
- 基本設定・エスカレーション・祝日を保存すると、**未返信中の全会話のリマインド予定を再計算**し、
  「保存しました（12件の予定を再計算）」と件数を返す。

## 状態バッジの色

|---------|-----|
| 未対応 | 赤 |
| 対応中 | 橙 |
| 対応済み | 緑 |
| 要確認 | 紫 |
